Key Takeaways

Vulnerability

The production backend accepted one universal static OTP for every customer account.

Attack requirement

An attacker needed only a registered user’s email address to trigger the authentication bypass successfully.

Victim interaction

The attack required no mailbox access, password, active session, legitimate OTP, or interaction from the victim.

Result

The authentication bypass issued valid access and refresh tokens directly to the unauthenticated attacker.

Impact

The attacker gained full account control with every permission assigned to the compromised registered user.

Risk level · Critical

Any registered customer account could be taken over without authentication by using the universal static OTP.

Technical details

Primary security classification

OWASP Top 10:2025 – A07: Authentication FailuresCWE-287: Improper Authentication

Contributing weakness

A hardcoded or otherwise static authentication value in production may also be relevant to CWE-798: Use of Hard-coded Credentials, depending on the underlying implementation.

Possible root cause

Development or testing logic, environment configuration, or another implementation issue may have caused the static verification value to remain available in the production authentication flow.

Identity controls reviewed

Privileged and dormant accounts are included.

Recovery paths tested

Backups and dependencies have named owners.

External exposure monitored

Credentials, domains, and public-facing assets are covered.
